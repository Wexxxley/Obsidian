### **De volta ao App.jsx: A função `handleProcessVideo`**

Quando o botão é clicado na `HomeScreen`, esta função no `App.jsx` é disparada:

JavaScript

```
const handleProcessVideo = async (url) => {
  setIsLoading(true); // 1. Trava a UI
  try {
    // 2. Chama o Backend
    const response = await fetch(`${API_BASE}/process`, { ... });
    const data = await response.json();

    if (!response.ok) throw new Error(...);

    // 3. Sucesso!
    setVideoData(data); // Salva o JSON gigante das legendas
    setScreen('video'); // Troca a tela para o Player
  } catch (error) {
    alert(`Erro: ${error.message}`);
  } finally {
    setIsLoading(false); // 4. Destrava a UI (dando certo ou errado)
  }
};
```

**Análise do Fluxo de Dados:**

1. **Imediato (`setIsLoading(true)`):** O React re-renderiza o `App`. Ele passa `isLoading={true}` para a `HomeScreen`. O botão fica cinza e o texto muda para "Processando...".
    
2. **Assíncrono (`await fetch`):** O navegador faz a requisição para o seu servidor (`localhost:3000/api/process`). O código "pausa" aqui esperando a resposta.
    
3. **Atualização de Estado (`setVideoData` e `setScreen`):**
    
    - Ao receber os dados, o `App` guarda tudo em `videoData`.
        
    - Muda `screen` para `'video'`.
        
    - **Consequência:** Na próxima renderização, a condição `screen === 'home'` será falsa (removendo a Home) e a condição `screen === 'video'` será verdadeira (montando o Player).
