- **@Entity**: Define que a classe é uma tabela. Podemos dar um nome a ela com tableName.
- **@PrimaryKey**: Toda tabela precisa de uma chave primária única. Usamos autoGenerate = true para o Room cuidar dos números (1, 2, 3...) para nós.
- **@ColumnInfo**: Define o nome da coluna no SQLite. Se não usar, o Room usa o nome da variável, mas é boa prática definir nomes claros.
- **ID 0**: definir o ID inicial como 0 sinaliza ao Room que ele deve gerar um novo número automaticamente.

```
package com.exemplo.noteapp.model

import androidx.room.ColumnInfo
import androidx.room.Entity
import androidx.room.PrimaryKey

/**
 * Representa a tabela "notes" no banco de dados SQLite.
 * Cada propriedade da classe representa uma coluna.
 */
@Entity(tableName = "notes") // Define o nome da tabela no banco de dados
data class Note(
    
    // O ID é a nossa Chave Primária Única. 
    // O banco de dados vai incrementar este número automaticamente.
    @PrimaryKey(autoGenerate = true)
    @ColumnInfo(name = "note_id")
    val id: Long = 0, // Definido como 0 para ativar o auto-incremento do Room

    @ColumnInfo(name = "note_title")
    val title: String,

    @ColumnInfo(name = "note_description")
    val description: String
)
```

### 4. Por que usamos Coroutines com Room?

A transcrição menciona que operações de banco de dados **não podem** rodar na _Main Thread_ (Thread principal).

- **Motivo:** Se o banco de dados demorar para responder, a tela do usuário trava (ANR - App Not Responding).
    
- **Solução:** Usamos as **Coroutines**. Elas permitem que o app faça a busca no banco em "segundo plano" e atualize a tela apenas quando os dados chegarem, de forma assíncrona.
