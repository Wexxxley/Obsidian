### **1. Entities**

- **@Entity**: Define que a classe é uma tabela. Podemos dar um nome a ela com tableName.
- **@PrimaryKey**: Toda tabela precisa de uma chave primária única. Usamos autoGenerate = true para o Room cuidar dos números (1, 2, 3...) para nós.
- **@ColumnInfo**: Define o nome da coluna no SQLite. Se não usar, o Room usa o nome da variável, mas é boa prática definir nomes claros.
- **ID 0**: definir o ID inicial como 0 sinaliza ao Room que ele deve gerar um novo número automaticamente.

### **2. DAO**

O DAO é uma interface anotada com `@Dao`. Você não precisa escrever o código de como inserir ou deletar; você apenas define a "assinatura" do método e o Room gera a implementação SQL automaticamente em tempo de compilação.

A regra de ouro do Android é: Nunca faça operações de banco de dados na Main Thread.
- **`suspend`**: Usamos esta palavra-chave para que o Kotlin saiba que essa função pode demorar e deve ser executada em uma Coroutine sem travar a tela.
- **`OnConflictStrategy`**: Quando você tenta inserir uma nota com um ID que já existe, ocorre um conflito. A estratégia `REPLACE` diz ao Room: "Se já existir, substitua pela nova".

---
### 4. Consultas com SQL e Reatividade (Flow)

Para buscas personalizadas, usamos a anotação `@Query`.

- **`Flow<List<Note>>`**: Esta é a parte mais poderosa. Ao retornar um `Flow`, o Room se torna "reativo". Se você adicionar uma nota nova no banco, o `Flow` emitirá automaticamente uma nova lista atualizada para a sua UI, sem que você precise fazer uma nova consulta manual.

### 5. Exemplo Completo em Código: `NoteDao.kt`

Aqui está o arquivo completo, seguindo as melhores práticas e os comandos SQL explicados na aula:

Kotlin

```
package com.example.testesimg.data.dao

import androidx.room.Dao
import androidx.room.Delete
import androidx.room.Insert
import androidx.room.OnConflictStrategy
import androidx.room.Query
import androidx.room.Update
import com.example.testesimg.data.entities.Note
import kotlinx.coroutines.flow.Flow

@Dao
interface NoteDao {

    // 1. Inserir uma nota. Se o ID já existir, substitui (REPLACE).
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun addNote(note: Note)

    // 2. Atualizar uma nota existente.
    @Update
    suspend fun updateNote(note: Note)

    // 3. Deletar uma nota específica.
    @Delete
    suspend fun deleteNote(note: Note)

    // 4. Buscar todas as notas. 
    // Retorna Flow para que a UI seja atualizada automaticamente em tempo real.
    // Não precisa de 'suspend' porque o Flow já opera de forma assíncrona.
    @Query("SELECT * FROM notes ORDER BY note_id ASC")
    fun getAllNotes(): Flow<List<Note>>

    // 5. Buscar uma nota específica pelo ID.
    // Usamos :id para referenciar o parâmetro da função dentro do SQL.
    @Query("SELECT * FROM notes WHERE note_id = :id")
    suspend fun getNoteById(id: Long): Note

    // 6. Deletar todas as notas da tabela.
    @Query("DELETE FROM notes")
    suspend fun deleteAllNotes()
}
```

### Explicação de pontos específicos do código:

- **`SELECT * FROM notes`**: O asterisco (`*`) seleciona todas as colunas da tabela que definimos na Entity.
    
- **`ORDER BY note_id ASC`**: Organiza da nota mais antiga para a mais recente (1, 2, 3...).
    
- **Segurança em Tempo de Compilação**: Como mencionado na aula, se você escrever `SELECT * FROM notas` (com "a" no final por erro), o Android Studio mostrará um erro vermelho **antes** de você rodar o app. Isso evita bugs comuns de digitação em SQL.
