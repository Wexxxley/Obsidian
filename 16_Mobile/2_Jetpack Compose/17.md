### **1. Application**

A classe Application é o primeiro componente que o Android inicia. Ela é o lugar ideal para manter o Singleton do Banco de Dados e do Repositório, garantindo que eles vivam enquanto o app estiver aberto.

 **by lazy:** adia a criação do objeto até o momento em que ele é solicitado pela primeira vez. Se o app abrir e não precisar do banco imediatamente, ele não gastará memória ou processamento para criá-lo.

### 2. Populando o database

Para que o usuário não abra o app e veja uma tela vazia, usamos um **Callback**. Ele intercepta a criação do banco de dados e insere dados padrão.


Como o Room proíbe operações na Thread Principal, precisamos definir um **CoroutineScope** dentro da classe de banco de dados. CourotineScope é o "espaço de trabalho" das threads secundárias.
- **SupervisorJob:** Garante que, se uma inserção de nota falhar, as outras notas continuem tentando ser inseridas.
    
- **Dispatchers.IO:** O "trabalhador" especializado em tarefas de disco (Input/Output), como salvar arquivos no SQLite.
    


Como agora o método `getDatabase` pede um `scope`, precisamos ajustar nossa classe de aplicação:

Kotlin

```
class NoteApplication : Application() {
    // Criamos um escopo global para a aplicação
    private val applicationScope = CoroutineScope(SupervisorJob() + Dispatchers.Main)

    val database by lazy { NoteDatabase.getDatabase(this, applicationScope) }
    val repository by lazy { NoteRepository(database.getNoteDao()) }
}
```

### Resumo Técnico

1. **NoteApplication:** Centraliza as instâncias e evita que o sistema recrie o banco toda hora.
    
2. **`by lazy`:** Economiza recursos no boot do app.
    
3. **Manifesto:** Registrar o nome da aplicação é o que "ativa" esse código global.
    
4. **Callback + Coroutine:** Permite que o app venha "pré-carregado" com dados sem travar a interface do usuário.
