

---
UML é uma notação gráfica para modelagem de software. A linguagem define um conjunto de diagramas para documentar e ajudar no design de sistemas de software, particularmente sistemas orientados a objetos.

UML é o resultado de um esforço para unificar as notações gráficas que surgiram no final das décadas de 80. 

---
### **UML como Esboço**

Consiste em usar a UML para criar diagramas **leves e informais** de partes do sistema, principalmente para **comunicação entre desenvolvedores**.

    - Usada em dois cenários principais:
        
        - **Engenharia Avante (Forward Engineering):** Desenvolvedores usam esboços para discutir e analisar alternativas de design _antes_ de codificar . Ex: Esboçar classes e relacionamentos para implementar uma história de usuário .
            
        - **Engenharia Reversa (Reverse Engineering):** Desenvolvedores usam esboços para explicar ou discutir uma funcionalidade _já implementada_ . Ex: Um dev experiente explicando código para um novato usando diagramas .
            
    - **Características dos esboços:** Não buscam ser completos/detalhados, podem ser feitos em quadros brancos (e depois fotografados/apagados), não exigem ferramentas CASE complexas, não geram código, e usam apenas um subconjunto dos diagramas UML .
        

**Por que usar UML para Esboços?**

- Mesmo sendo informais, usar uma notação padronizada (mesmo que parcialmente) é melhor do que criar diagramas _ad hoc_ cujo significado pode não ser claro para todos .
    
- O conhecimento básico de UML é útil, pois ela é frequentemente usada em livros, tutoriais e documentações técnicas (inclusive neste livro para explicar Padrões de Projeto no Cap. 6) .
    

**Público dos Modelos:**

- Diferente dos documentos de requisitos (que podem ser lidos por usuários finais), os modelos de software (como diagramas UML) são primariamente escritos **por e para desenvolvedores** .
    

**Mundo Real:**

- Uma pesquisa com desenvolvedores mostrou que eles criam esboços com frequência para diversas finalidades (design de arquitetura, novas funcionalidades, explicar tarefas, analisar requisitos, entender código) . Muitos desses esboços são arquivados e cerca de metade contém elementos de UML, reforçando a relevância de aprender UML para comunicação e design informal .
