Vamos começar analisando a versão final da imagem que você irá construir neste capítulo, para entender como ela foi projetada.

Os exercícios usarão uma aplicação simples chamada **web-ping**. O objetivo dela é verificar se um site está no ar: ela roda em um contêiner e faz requisições HTTP para uma URL (por padrão, o blog do autor) a cada 3 segundos2.

#### Baixando a imagem (Pull)

O software de distribuição é embutido na plataforma Docker. Você pode deixar o Docker baixar imagens automaticamente quando tenta rodar um contêiner, ou pode baixá-las explicitamente.

Tente agora:

Baixe a imagem da aplicação web-ping:

docker image pull diamol/ch03-web-ping:2e

O que acontece aqui?

A saída do comando mostra algo interessante sobre como as imagens são armazenadas3:

- **Imagem Lógica:** Logicamente, a imagem é um objeto único (como um arquivo zip gigante contendo a aplicação e tudo o que ela precisa).
    
- **Armazenamento Físico (Camadas):** Fisicamente, a imagem é armazenada como muitos arquivos pequenos chamados **layers** (camadas). O Docker monta essas camadas para criar o sistema de arquivos do contêiner. Quando todas as camadas são baixadas, a imagem está pronta para uso.
    

A imagem veio do **Docker Hub**, que é o registro padrão onde o Docker procura imagens.

#### Rodando a aplicação

Agora vamos ver o que o app faz.

Tente agora:

Rode o contêiner em segundo plano (--detach ou -d) e dê um nome a ele (--name):

docker container run -d --name web-ping diamol/ch03-web-ping:2e

Agora, verifique os logs para ver o app funcionando:

docker container logs web-ping

Você verá que o app está pingando o blog do autor (`blog.sixeyed.com`) a cada 3000ms (3 segundos)4.

#### Configuração via Variáveis de Ambiente

Esse aplicativo parece inútil se só servir para pingar o blog do autor. Mas ele não é "hardcoded" (fixo no código). Ele foi programado para ler configurações a partir de **Variáveis de Ambiente** do sistema.

No Docker, você pode injetar essas variáveis quando inicia o contêiner.

Tente agora:

Remova o contêiner antigo e inicie um novo, mas desta vez alterando o alvo (TARGET) para o Google:

1. `docker rm -f web-ping`
    
2. docker container run --env TARGET=google.com diamol/ch03-web-ping:2e
    
    (Nota: --env ou -e define a variável).
    

Agora, a saída mostrará: `Pinging: google.com`5.

A lição importante:

A imagem Docker vem com configurações padrão, mas o autor da imagem deve permitir flexibilidade. O código da aplicação web-ping procura uma variável chamada TARGET. Se você fornecer um valor diferente na hora de rodar (docker run), o comportamento do app muda sem você precisar alterar o código ou reconstruir a imagem.

### 3.2 Escrevendo seu primeiro Dockerfile

O **Dockerfile** é um script simples contendo instruções para empacotar uma aplicação. A saída desse script é uma Imagem Docker.

A sintaxe é fácil de aprender. Abaixo está o Dockerfile completo para a aplicação `web-ping` (Listagem 3.1 do livro)6:

```Dockerfile
FROM diamol/node:2e
ENV TARGET="blog.sixeyed.com"
ENV METHOD="HEAD"
ENV INTERVAL="3000"
WORKDIR /web-ping
COPY app.js .
CMD ["node", "/web-ping/app.js"]
```

Entendendo as Instruções 7:

1. **`FROM`**: Especifica a imagem base. Toda imagem tem que começar a partir de outra. Aqui, começamos com `diamol/node:2e`, que já tem o Node.js instalado.
    
2. **`ENV`**: Define valores para variáveis de ambiente (Environment Variables). Aqui definimos o alvo padrão, o método HTTP e o intervalo.
    
3. **`WORKDIR`**: Cria um diretório dentro do sistema de arquivos da imagem e define ele como o diretório atual de trabalho. (Equivale a fazer `mkdir` e depois `cd` no Linux/Windows).
    
4. **`COPY`**: Copia arquivos ou diretórios do seu computador local (o host) para dentro da imagem. Aqui, estamos copiando o código da aplicação (`app.js`) para a pasta de trabalho.
    
5. **`CMD`**: Especifica o comando que será executado quando o Docker iniciar um contêiner a partir desta imagem. Aqui, ele manda o Node executar o arquivo javascript.
    

Essas 5 instruções são praticamente tudo o que você precisa para empacotar suas próprias aplicações.
